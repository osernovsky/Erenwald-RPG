# Типы объектов и экземпляры

Черновик к согласованию. Рабочий пример каталога находится в [world/object_types.yaml](../world/object_types.yaml).

## Каталог типов

Один YAML-документ с обязательными ключами `schema_version: 1` и `types`. `types` — отображение идентификатора типа в определение с обязательным непустым `components`. Идентификатор типа состоит из строчных латинских букв, цифр и подчёркиваний и начинается с буквы. Идентификаторы типов составляют отдельное пространство имён.

`components` — отображение имени компонента в структуру с необязательными ключами `config` и `initial`. `config` задаёт параметры правил. `initial` задаёт начальные значения изменяемых полей. Значение `{}` выбирает компонент с его стандартными параметрами. Имена, поля, типы значений и сочетания компонентов проверяются загрузчиком. Реализация действий принадлежит компонентам, поэтому новый тип из известных компонентов добавляется в каталог.

| Компонент | `config` | `initial` и поведение |
| --- | --- | --- |
| `container` | Нет полей в первой версии. | Содержимое определяется размещением. Допустимы вложенные предметы. При наличии `openable` доступ к содержимому требует открытия. |
| `openable` | Нет полей. | `is_open` — логическое значение, по умолчанию `false`. Действия `open` и `close`. |
| `lockable` | `key_code` — обязательный после объединения строковый код ключа. | `is_locked` — логическое значение, по умолчанию `false`. Требует `openable`. Открытие запертого объекта запрещено, запереть можно закрытый. |
| `portable` | Нет полей. | Разрешает перенос доступного предмета действием `take` и другими правилами перемещения. |
| `breakable` | Нет полей. | `is_broken` — логическое значение, по умолчанию `false`. Эффекты поломки и её связь с другими компонентами предстоит согласовать. |
| `readable` | `text` — обязательный после объединения непустой текст. | Действие `read` возвращает текст доступного предмета. |
| `usable` | `action: unlock` и `key_code` — обязательные после объединения поля первого варианта. | Ключ в инвентаре может отпереть доступную цель с совпадающим кодом. Код — параметр совместимости, отдельные ключи сохраняют собственные ID. |

`searchable`, `weapon`, `armor` и `light_source` остаются кандидатами для последующих схем. Первоначальное действие `search` работает с областью, которую задаёт локация или доступный контейнер. Черновик описывает предполагаемую семантику компонентов. Объём реализации первого среза указан в [дорожной карте](ROADMAP.md).

## Определение экземпляра

| Поле | Назначение |
| --- | --- |
| `id` | Обязательный глобальный стабильный ID с префиксом `obj.`. |
| `type` | Обязательная ссылка на тип из каталога. |
| `name` | Обязательное русское отображаемое имя. |
| `description`, `aliases` | Необязательные текст осмотра и список дополнительных имён. |
| `contents` | Необязательный список вложенных экземпляров той же формы. Допустим у типа с `container`. |
| `overrides` | Необязательное отображение имени имеющегося компонента в его изменённые `config` или `initial`. |
| `perception` | Необязательное правило восприятия из [формата локации](LOCATION_FORMAT.md). |

Композиция выполняется в порядке «значения компонента по умолчанию → значения типа → переопределения экземпляра». Переопределяется целое значение отдельного объявленного поля. Списки и составные значения при появлении таких полей заменяются целиком. Способность отличать отсутствующее поле от явного `false` или `0` обязательна для Go-декодера. `null`, YAML-слияния, добавление и удаление компонентов через `overrides` отклоняются. Загрузчик проверяет итоговый состав и отклоняет несовместимые состояния, например открытый запертый объект.

## Пример

У `wooden_box` есть `container`, `openable` с начальным `is_open: false`, `portable` и `breakable`. В [локации entry](../world/locations/demo/entry.yaml) экземпляр `obj.entry.box` задаёт имя и два вложенных экземпляра. У книги `obj.entry.book` меняется только текст компонента `readable`. При регистрации книга получает начального родителя `obj.entry.box` и собственный ID. Ящик и книга продолжают существовать по этим ID после переноса. Состояние `openable.is_open` сохраняется отдельно от определения типа. Состояние предмета без изменяемых компонентов хранится как пустой объект `{}`.

Глобальные ID обозначают единичные сущности. Стеки отложены до согласования правил количества, слияния, разделения и идентичности. Уникальные предметы всегда остаются отдельными экземплярами.
