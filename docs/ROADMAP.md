# Дорожная карта

## Этап 1. Согласование модели

- Проверить каталог компонентов и два файла локаций.
- Утвердить правила размещения, совместимости сохранений и формата условий и эффектов. Открытые вопросы перечислены в [архитектурных решениях](DECISIONS.md).
- Утвердить состав первого вертикального среза.

## Этап 2. Первый вертикальный срез после согласования

1. Создать Go-модуль и выбрать YAML-парсер и SQLite-драйвер. Проверить строгий режим YAML, поддержку `database/sql` и возможность сборки на macOS и Ubuntu без CGO.
2. Загрузить примеры, разрешить глобальные ID и реализовать минимальное сохранение на временной SQLite. Добавить правила исключения локальных сохранений, сопутствующих файлов SQLite и секретов перед работой с ними.
3. Реализовать открытие ящика, взятие тетради, сохранение и повторный вход. Добавить переходы по состоянию заслонки и одноразовый эффект на заслонку в ещё не посещённой локации. Для демонстрации достаточно локального CLI с командами и меню. Оставшиеся компоненты и варианты восприятия подключать по мере реализации и проверки их правил.

## Приёмочные сценарии реализации

- Первый вход создаёт строки по мере обращения. Повторный вход и перезапуск сохраняют открытость ящика, прежние ID и тетрадь в инвентаре.
- Новый предмет в локации и новый предмет внутри перенесённого контейнера появляются с правильными родителями. Старые записи сохраняются.
- Направленный переход виден при закрытой заслонке и доступен после открытия. Правило из приёмной меняет состояние заслонки до входа в кладовую и срабатывает один раз.
- Скрытый ключ существует до обнаружения. Доступ к нему появляется после поиска. Повторный поиск при тех же обстоятельствах даёт тот же результат.
- Перенос вложенного контейнера сохраняет ID и отклоняет помещение контейнера в своего потомка.
- Ошибка эффекта откатывает состояние, размещение, шаг и строки журнала. Повтор команды с тем же ID не меняет состояние после успешной фиксации.
- Дубликаты, неверные ссылки, неизвестные поля, несовместимые сохранения и недопустимые начальные состояния дают диагностику.

Для проверки реализации использовать `gofmt`, `go vet ./...` и `go test ./...`. Сквозные сценарии используют изолированную временную базу.

Следующие этапы определяются после проверки среза. Боевые правила, сюжет и сетевой интерфейс требуют отдельных спецификаций.
