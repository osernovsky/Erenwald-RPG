# Архитектура мира

Черновик к согласованию. Объём первого этапа описан в [дорожной карте](ROADMAP.md).

## Структура проекта

| Путь | Ответственность |
| --- | --- |
| `world/object_types.yaml` | Единый каталог типов объектов. |
| `world/locations/<region>/<location>.yaml` | Самостоятельные локации, которые загрузчик находит при обходе каталогов. |
| `docs/` | Спецификации, решения и план реализации. |
| `cmd/erenwald/` | Будущий локальный CLI с текстовыми командами и меню. |
| `internal/world/` | Типизированные определения, чтение YAML, проверка и глобальный индекс. |
| `internal/engine/` | Правила компонентов, размещение, восприятие, действия, условия и эффекты. |
| `internal/store/sqlite/` | Хранение состояния, миграции и работа с транзакцией через `database/sql`. |
| `go.mod`, `go.sum` | Модуль Go и зависимости при начале реализации. |

CLI вызывает движок и отображает его результат. Движок принимает структурированное намерение и работает с определениями мира и транзакцией, предоставленной хранилищем. На границах ввода-вывода используется `context.Context`. Тесты пакетов располагаются рядом с кодом, сквозные сценарии работают с временной SQLite.

## Определение, экземпляр и состояние

| Слой | Пример |
| --- | --- |
| Тип | `wooden_box` задаёт состав компонентов и начальные значения. |
| Определение экземпляра | `obj.entry.box` задаёт имя, начальных детей и переопределения. |
| Состояние экземпляра | SQLite хранит существование, открытость и текущее размещение. |
| Восприятие | Движок вычисляет, что игрок видит и к чему может обратиться сейчас. SQLite хранит его открытия и знания. |
| Представление | Движок формирует текст по определениям, текущему состоянию и истории посещений. |

При запуске загрузчик читает все YAML, строит единый индекс и проверяет ссылки, в том числе межлокационные. Индекс связывает каждый ID с его видом, определением и начальным родителем при его наличии. Локация может ссылаться на общий каталог и на ID из других файлов. Направленные переходы образуют граф, каждый обратный переход объявлен явно. Имя файла и каталог служат для организации контента. ID остаётся стабильным при перемещении файла или переименовании игрового объекта.

Проверенный набор определений используется весь сеанс. Новая версия контента загружается при следующем запуске и проверяется на совместимость с сохранением. Каждое действие работает с одним снимком определений и одной транзакцией. Эффект по глобальному ID может изменить объект до первого посещения его локации.

## Размещение и восприятие

Размещение предмета задаётся одним непосредственным родителем в SQLite. Это локация, объект с компонентом `container` или существо, включая игрока. Помещение предмета в инвентарь означает выбор игрока его родителем. Сам игрок и прочие существа размещаются в локациях. Комната предмета вычисляется по цепочке родителей. Перенос контейнера переносит и его содержимое без обновления записей детей. Начальный родитель из YAML нужен при регистрации, текущий берётся из SQLite.

Характеристики сущности рассматриваются по отдельности.

- **Существование.** Определённая сущность существует до обращения к ней, если её сохранённый статус допускает это. Ленивое создание строки само по себе не влияет на мир. Статус `removed` исключает сущность из текущего мира и сохраняет её ID. Сломанный предмет может оставаться в мире.
- **Физическое состояние.** Например, крышка открыта, замок заперт, предмет сломан. Состояние меняют действия и события.
- **Текущая видимость и доступность.** Состав сцены зависит от актуального размещения, границ контейнеров и условий восприятия. Видимая цель может быть недоступна для конкретного действия. Игрок может видеть выход и узнать, что путь перекрыт.
- **Обнаружение.** Игрок наблюдал сущность непосредственно, в том числе при пассивном восприятии или активном поиске. Этот факт сохраняется.
- **Знание.** Игрок знает о сущности из наблюдения или из явного эффекта, например из текста записки. Знание сохраняется после ухода и не выдаёт текущее местоположение предмета.

Игрок выбирает известную и доступную цель по русскому имени, синониму, пункту меню или через уточнение при неоднозначности. Область осмотра и поиска — локация или доступный контейнер. При обнаружении цели движок сохраняет знание до формирования результата и списка команд. Поиск первого этапа детерминирован. У обязательного пути должен быть надёжный способ обнаружения и прохождения.

## Игровой шаг

Интерфейс разбирает ввод в намерение. Движок уточняет цель, инициализирует необходимые записи, проверяет видимость, доступность и условия, применяет эффекты и правила событий, обновляет шаг и журнал. Результат отправляется после фиксации транзакции. Шаг определяется правилами действий. Время между сеансами не меняет состояние.
