# Формат локации

Черновик к согласованию. Формат показан в файлах [приёмной](../world/locations/demo/entry.yaml) и [кладовой](../world/locations/demo/store.yaml).

## Правила загрузки

Каждый файл содержит одну локацию в одном документе YAML 1.2, в UTF-8. Загрузчик читает каталог типов и рекурсивно обходит `world/locations/`. Затем он проверяет глобальную уникальность ID и разрешает ссылки, включая ссылки вперёд. Порядок файлов не влияет на результат. [Спецификация YAML 1.2.2](https://yaml.org/spec/1.2.2/)

Предлагаемый формат ID — префикс из `location`, `obj`, `actor`, `exit`, `event` и один или несколько сегментов через точку. Каждый сегмент соответствует `[a-z][a-z0-9_]*`. Сегменты помогают автору читать файл. Например, `obj.entry.book` сохраняет этот ID и в инвентаре, и в кладовой. `actor.player` зарезервирован для игрока.

Отклоняются неизвестные поля и версии, дубликаты ключей и ID, неверные типы, висячие или несовместимые ссылки, `null`, явные YAML-теги, якоря, псевдонимы и ключи слияния. Загрузчик декодирует поля в типизированные структуры и ограничивает размер документа и глубину вложенности. Диагностика указывает файл и путь поля. Исполняемая логика задана в Go. YAML содержит параметры и ссылки на операции из закрытого списка.

## Поля локации

| Ключ | Обязательность и содержимое |
| --- | --- |
| `schema_version` | Обязательное целое число `1`. |
| `id`, `name` | Обязательные ID локации и отображаемое имя. |
| `descriptions` | Обязательное отображение с непустым текстом `first_visit` и необязательным `revisit`. При отсутствии `revisit` используется `first_visit`. |
| `objects` | Список [экземпляров объектов](OBJECT_TYPES.md), изначально размещённых в локации. |
| `actors` | Список существ, изначально размещённых в локации. Обязательны `id`, `role` (`npc` или `enemy`) и `name`. Допустимы `description`, `aliases`, `perception` и `inventory` со списком начальных экземпляров предметов. |
| `exits` | Список направленных переходов, исходящих из этой локации. |
| `events` | Список локальных правил событий в порядке применения. |

Отсутствующий список считается пустым. `aliases`, если указано, содержит непустые строки. Описания посещений задают текст сцены, а движок дополняет их актуальными видимыми объектами, существами и выходами. Роль существа задаёт его категорию и оставляет механику общения и боя для расширения формата.

## Переход

Обязательны `id`, `name` и `to` с ID локации назначения. Допустимы `description`, `aliases`, `perception`, `available_when` и `blocked_text` для заблокированного видимого перехода. Исходная локация определяется файлом. Связь в обратную сторону задаётся отдельным переходом с собственным ID. Два перехода могут проверять состояние одной заслонки.

## Восприятие

У объекта, существа или перехода необязательный блок `perception` задаёт `mode`, условие `when` и, для режима `passive`, обязательный целочисленный `min_score` от нуля. По умолчанию используется `obvious`. В первом срезе оценка пассивного восприятия игрока равна 1.

| Режим | Как происходит обнаружение |
| --- | --- |
| `obvious` | При наблюдении области, если выполняется `when`. |
| `passive` | При наблюдении области, если выполняется `when` и оценка достигает `min_score`. |
| `search` | При активном поиске в области, если выполняется `when`. |

Область включает непосредственное доступное содержимое локации или открытого доступного контейнера. Закрытые контейнеры перекрывают восприятие содержимого. Если цель уже обнаружена, её можно снова увидеть в доступной области при выполнении `when`. Журнал обнаружений не раскрывает цель за закрытой крышкой или в другой комнате. Условия восприятия и условия прохождения проверяются независимо.

## Условия, эффекты и события

`perception.when`, `available_when` и `events[].when` — списки условий, все элементы которых должны выполниться. Пустой список считается истинным. В черновике предусмотрены две операции для демонстрационного сценария:

| Операция | Обязательные поля кроме `kind` | Семантика |
| --- | --- | --- |
| Условие `state_is` | `target`, `component`, `field`, `value` | Сравнить сохранённое поле существующего объекта с типизированным значением. Для удалённого объекта возвращает ложь. |
| Эффект `set_component_state` | `target`, `component`, `field`, `value` | Изменить объявленное изменяемое поле существующего объекта, проверив допустимость нового состояния. |

Ссылки и типы значений проверяются при загрузке. Проверка условия вычисляет логическое значение и оставляет знание игрока без изменений. Она может инициализировать отсутствующую строку в текущей транзакции. Эффект обращается к цели по ID, поэтому поиск по имени и проверка знания игрока здесь не требуются.

Событие требует `id`, `trigger` с `action` и `target`, и непустой список `effects`. Необязательны `when`, `once` (по умолчанию `false`) и `message`. Правила берутся из локации, где началось действие игрока. После успешного основного действия выполняются совпавшие правила в порядке списка. Следующее правило видит изменения предыдущего. Эффект изменяет состояние без повторного запуска правил действий. В примере `trigger.action: open` связан с конкретным открываемым объектом. Допустимые сочетания действия и цели задаёт движок.

Новые предикаты, например наличие предмета в инвентаре, и эффекты, например сообщение игроку о сущности, добавляются после согласования их типизированных параметров и правил выполнения.
